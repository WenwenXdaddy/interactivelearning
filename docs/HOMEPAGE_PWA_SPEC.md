## Accepted independent review amendments (normative)

These amendments supersede any broader wording above. Worker activation occurs naturally after controlled readers close; no force activation button. Exact-resume acceptance is capability-specific and never promises step precision for gold or the field guide. All original inline bodies remain identical; only explicit external portal scripts are added to generated course pages.

1. **Define exact-resume capabilities per course.** The spec asks for all 14 adapter contracts but leaves the selector and restore behavior to inference. The common `.lesson[data-lesson]` pattern does not cover gold or the data center course; step IDs differ among the others. Add the table below to the spec or an implementation contract. The bridge must record only a stable current lesson/step identifier derived from the visible rendered reading area. It should restore by clicking an existing lesson control (or using the data center course's own hash route), then scroll to a validated step element once visible. It must not call private course functions, edit existing scripts, read existing storage values, or treat a source citation jump, glossary, dialog, or quiz as a reading position. A step with no stable ID gets lesson-only resume. If a course's actual browser behavior cannot satisfy this contract, mark it as recent visit only in the final acceptance matrix; do not claim exact resume for that course.

   | Course(s) | Observed source navigation | Candidate resume level |
   | --- | --- | --- |
   | `gold-volatility` | `section#lesson0` … `#lesson9`; nav and in-page `data-go`, `go(i)`; `.step` elements have no IDs | Lesson only, via existing `data-go` control; no exact step claim |
   | `us-data-center-buildout` | Rendered `#main`; `#learn/<number>` hash router and `navigate(hash)` | Lesson via validated `#learn/<number>` route; no stable step ID in source |

   The bridge should verify each stored course slug, lesson ID, step ID, and adapter version against the current DOM before offering exact resume. Capture the current step from the visible lesson and viewport, with a debounce; initial load or programmatic jumps must not immediately overwrite a valid saved position with station zero. Acceptance should exercise capture, homepage return, reload, and restore for each claimed level on every course, plus invalid/deleted ID fallback.

2. **Specify transactional course-cache replacement.** `CacheStorage` is not a transaction over multiple files. Use immutable, owned, versioned cache names for each course bundle (HTML, notes, preview, bridge dependency), and a small owned metadata cache with one active-generation pointer per course. Serialize save/update/remove for each slug. Fill a new generation, verify every expected URL has a successful same-origin response and a cache match, then atomically replace the pointer entry. Only then show “saved” and remove obsolete owned generations. On fetch, quota, verification, or pointer-write failure, delete the incomplete generation and keep the old active pointer/cache. Derive the saved list and status from the pointer **and** actual cache entries, never solely localStorage. A missing/corrupt pointer or missing asset is “needs repair,” not “saved.” Shell-cache versions need the same ownership boundary; activate a new shell only after a complete install, and never delete active course generations during shell cleanup. Explicitly list the expected URL set and alias normalization for `/`, `/index.html`, `/courses/<slug>/`, and `/courses/<slug>/index.html`.

3. **Make worker activation safe across open readers.** An “apply update” button that calls `skipWaiting()` can replace the active worker while another tab is reading. State that a newly installed worker remains waiting until existing controlled tabs close; the UI may show an available update and ask the user to close the other tabs and reopen. Do not call `skipWaiting()` or `clients.claim()` in the normal update path. Course bundle refresh can remain an explicit action under the active worker using the generation-pointer protocol above. Browser acceptance must verify an old reading tab remains usable while a new worker waits and that the new worker takes control only after the tabs close/reopen.

4. **Update the checker and CSP contract precisely.** `scripts/check.mjs` currently requires literal `connect-src 'none'`; the approved contract is `connect-src 'self'; worker-src 'self'` with no external host or unsafe script allowance. The checker also treats all inline scripts as original but does not validate the approved new external bridge/PWA scripts. Preserve equality of source and generated inline script bodies, continue hashing every authored inline script, and allow only explicit same-origin generated script paths with existence checks. Keep downloaded standalone HTML byte-identical to source. `scripts/serve.mjs` must recognize JS, PNG, and manifest MIME for local HTTP acceptance. The active Cloudflare edge inserts analytics/bot `<script>` tags into live HTML; the service worker can cache the returned HTML containing those tags. The enforceable boundary is to never fetch/cache those external scripts or any other off-origin request, and to keep the authored bundle and downloads intact. Do not claim that live cached HTML bytes equal source bytes or that the edge-inserted tags have been stripped without changing Cloudflare settings.

## Nonblocking refinements

- Label dates accurately. First git appearance of a course source is “added to this site,” not necessarily the original course publication date. Freeze the chosen first/last source commit dates and commit IDs in metadata; keep unknown values unknown and sort them last.
- Define the UI's offline “download bytes” as the sum of known same-origin response body sizes or measured received bytes, and show “size unavailable” when not known. A browser cache save is distinct from the existing standalone HTML download.
- Keep the homepage’s no-JavaScript catalog usable after moving details into `<details>`; controls that require JavaScript should appear only after enhancement. Check `320px` as well as `390px` for the compact hero and search placement.
- Use a distinct `jiadi-learning-portal` key for favorites/recent reading only. Existing course keys and memo contents stay opaque to the bridge.
